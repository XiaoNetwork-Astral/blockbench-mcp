# Blockbench 操作覆盖与兼容范围

本插件面向 Blockbench 桌面版的建模、贴图、动画与文件操作。最低版本为 5.1，当前现场验证版本为 5.1.6。常规目录包含 136 个核心工具和 14 个 YSM 工具；安装 Hytale 插件后再增加 12 个工具，共 162 项定义。实际可用功能同时取决于模型格式与已安装插件，应先调用 `inspect_capabilities`，需要特殊元素时再调用 `inspect_element_types`。

## 主要操作

| 领域 | 覆盖范围 | 使用边界 |
| --- | --- | --- |
| 项目与文件 | 创建、切换、复制、只读锁、原生项目打开保存、格式查询、文本或 JSON 模型导入、编译导出 | 操作目标是调用开始时可见的标签页；模型导入创建新标签页；二进制输入与缺少原生解析器的格式不由 `import_model` 接管 |
| 大纲与几何 | 组、方块、网格、骨架、骨骼、权重、选择、复制、删除、重命名、父子关系、集合、细分、挤出、切割等网格编辑 | 保留名称歧义检查和 Undo；新对象默认位于根层级 |
| 特殊元素 | 定位点、空对象、纹理网格、面向相机的平面、边界框、曲线；原生属性查询和修改 | `create_element` 使用已注册元素构造器；结构化几何使用专用工具；不开放实例引用或任意对象结构的直接写入 |
| 曲线与边界框 | `set_spline_points` 设置有序贝塞尔控制点、半径、倾角与闭合状态；`set_bounding_box` 设置范围 | 曲线限制控制点数量及生成工作量；保留纹理；控制点坐标属于元素局部空间 |
| 纹理、材质与绘画 | 创建、导入、分配、PBR、材质组、图层、选区、笔刷、填充、精确像素编辑、纹理设置和尺寸调整 | 编辑前隔离跨项目同步与外部文件关联；`resize_texture` 保持逻辑 UV 尺寸，缩放使用最近邻插值；整个图片尺寸包含动画全部帧 |
| UV | 方块和网格的 UV 读取、修改、映射、选区与验证 | 纹理像素尺寸、逻辑 UV 尺寸和模型坐标分别处理 |
| 动画 | 动画与关键帧的创建、编辑、复制、插值、时间线检查、批量处理、预览与姿态验证 | 使用当前项目的动画与原生动画器；不保留后台项目预览状态 |
| 动画控制器 | 查询、创建、完整状态图替换、重命名、初始状态、跳转条件、混合、粒子和声音声明、删除 | 验证动画引用和状态跳转后再修改；设置状态图不主动开始播放；删除仅影响项目，文件单独导出 |
| 动画文件 | 查询 `AnimationCodec`，导入与导出普通动画或控制器 | 调用现行 `loadFile`、`compileFile`、`compileAnimation`；不使用已弃用的 `Animator` 文件接口；写入已有文件须明确 `overwrite=true`，结果替换整个文件 |
| 视图与验收 | 相机、截图、显示变换、空间关系、UV/接触检查、快照、调试渲染、动画扫描、撤销与审计 | 截图期间的临时可见性和相机状态会恢复；按受影响对象核对结果 |
| YSM 与 Hytale | 保留工作区、扩展文件、Molang 检查和模拟，以及条件注册的 Hytale 操作 | Hytale 需要对应插件；未安装时不发布其工具。插件特有 API 仍有实验性部分 |

## 对照依据

本轮以 [Blockbench v5.1.6 源码](https://github.com/JannisX11/blockbench/tree/v5.1.6) 的格式能力、元素注册、原生 Undo、动画控制器与 AnimationCodec 实现为运行依据，并参考以下公开项目的操作设计：

- [jasonjgardner/blockbench-mcp-plugin](https://github.com/jasonjgardner/blockbench-mcp-plugin)：通用模型、纹理、动画及可选插件能力。
- [SwagRee/BlockBenchMCP](https://github.com/SwagRee/BlockBenchMCP)：Minecraft 几何批处理、按面绘画、UV 与纹理质量检查。
- [sosadly/blockbench-mcp](https://github.com/sosadly/blockbench-mcp)：几何、绘画、动画与视觉反馈的直接操作组合。

工具数量不能直接代表质量。本项目保留可见标签页、可撤销修改和明确文件目标的行为，并补齐特殊元素、曲线、控制器、现行动画文件 API 等操作缺口。任意 JavaScript 执行、通用界面点击、账号、协作会话和发布服务不属于工具覆盖承诺；第三方插件新增的全部专有界面也不能自动视为已支持。

协议层采用 [官方 TypeScript SDK 2](https://ts.sdk.modelcontextprotocol.io/v2/)，通过官方无状态兼容入口同时处理现代协议和旧客户端。HTTP 适配保留 Blockbench 支持的 `net` 模块，支持响应流、断开清理、来源检查和可选 Bearer 身份验证。

## 维护和验证

工具定义、参数与执行入口集中在各领域的 `defineTool` 定义中，由 `src/runtime/toolCatalog.ts` 统一供运行时和文档使用。参数通过 Zod 4 在官方 SDK 的调用入口校验。绘画、动画、元素属性与验证计算分别位于小型原生适配或功能模块。

`bun run check` 执行类型检查和单元测试；`bun run docs` 更新完整接口文档。依赖真实 Blockbench 的行为还需要独立实例验收。本轮现场覆盖曲线读回及 Undo/Redo、控制器文件往返及跳转恢复、只读拒绝、分层纹理缩放与裁切撤销、Java 模型导入。自动测试覆盖两个协议时代、流式传输、非法输入、部分导入失败与撤销归属。

安装文件通过 `bun run build` 生成，位于 `dist/blockbench_mcp.js`。更新后从该文件重新加载插件；文件名须保持不变。
