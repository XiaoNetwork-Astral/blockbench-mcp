# Incremental Blockbench modeling workflow

1. Start with the Blockbench tab that is currently visible. Inspect its format, texture resolution, Outliner, selection, object counts, textures, UV mode, animation state, and unsaved state before editing. Each project-scoped call targets whichever tab is visible when that call begins, so stop and re-inspect if the user changes tabs. Preserve unknown objects unless the user explicitly authorizes removal.
2. Plan the model as a hierarchy of body, major parts, connectors, attachments, and details. Create parent groups before their children. New nodes default to the Outliner root and duplicates stay beside the original, so supply the intended parent when building a hierarchy. Reparenting always requires an explicit destination, and ambiguous names must be resolved before editing.
3. Work from silhouette and proportions toward details. Build one small, inspectable stage at a time and read back its names, UUIDs, parents, transforms, texture references, and UVs. Validate one representative repeated or mirrored part before expanding it.
4. For every attachment, record what it connects to and check world-space position and per-axis bounds. Inspect front, side, top, and a three-quarter view. Two parts whose projection overlaps in one view but whose depth ranges are separated are not attached.
5. Verify Undo/Redo and project consistency after risky or batch operations. If the viewport, Outliner, search results, UUIDs, or counts disagree, stop creating new geometry and diagnose the current project instead of layering changes onto an uncertain state.
6. Ask the user to inspect the live model when references do not determine the intended hierarchy or depth, repeated attempts do not converge, or a correction could affect substantial finished work. Preserve the scene, identify the relevant names/UUIDs and uncertainty, and wait. Apply the user's correction to one small example before continuing in bulk.
7. Completion of geometry does not authorize saving over an existing file, closing unsaved tabs, deleting experiments, packaging, or publishing. Stop at the requested boundary and obtain explicit authorization for those separate actions.
